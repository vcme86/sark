# Sark on Cloudflare Workers

A single SSR page reads the last report from D1. A Cron Trigger updates that record and writes a
text report to R2 using native bindings. The Worker logs each completed run. Cloudflare serves
`/about.txt` and the browser bundles directly as static assets.

## Local development

Run `pnpm install` and `pnpm build` at the repository root. From this directory, create local
secrets and apply the D1 migration:

```sh
(umask 077; printf 'AUTH_SECRET=%s\nDEMO_TOKEN=%s\n' "$(openssl rand -hex 32)" "$(openssl rand -hex 32)" > .dev.vars)
pnpm db:migrate --local
pnpm dev
```

Open the URL printed by Vite. Use Cloudflare's local Scheduled handler to run the task once:

```sh
origin=http://localhost:5173
curl --fail-with-body "$origin/cdn-cgi/local/scheduled?cron=0+*+*+*+*"
curl --fail-with-body "$origin/api/report"
```

Refresh the page to see the D1 timestamp. The R2 response and the log entry should contain the same
timestamp. Use `pnpm typecheck` to regenerate Sark types and Wrangler binding types. Use
`pnpm build` followed by `pnpm preview` to serve the production build in local workerd.

The session endpoint exchanges the random demo token for a Sark Cookie. The demo token stays on
the server and is supplied by the operator. In a real application, use the application's normal
sign-in flow.

```sh
demo_token=$(sed -n 's/^DEMO_TOKEN=//p' .dev.vars)
printf '{"token":"%s"}' "$demo_token" |
  curl --fail-with-body --cookie-jar .build/demo.cookies \
    -H "Origin: $origin" -H 'Content-Type: application/json' \
    --data-binary @- "$origin/api/session"
curl --fail-with-body --cookie .build/demo.cookies "$origin/api/session"
```

## Deploy

Create a dedicated D1 database and R2 bucket in your Cloudflare account. Set the Worker name, D1
database name and ID, and R2 bucket name in `wrangler.jsonc`. Keep the binding names `DB` and
`FILES`. Create `.dev.vars.production` with fresh values for `AUTH_SECRET` and `DEMO_TOKEN` using
the same format as the local file. Both files are ignored by Git.

```sh
pnpm db:migrate --remote
pnpm build
pnpm run deploy --secrets-file .dev.vars.production
```

Wrangler uses the deployment configuration generated by the Cloudflare Vite plugin. In the
deployed application, check the page and session endpoints, then wait for the hourly UTC trigger
to run. Compare the page's D1 timestamp with the R2 report and the scheduled invocation in
Workers Logs. Request `/about.txt` and verify that it has no Sark `X-Request-Id` header. The
dynamic `/api/status` response includes one.
