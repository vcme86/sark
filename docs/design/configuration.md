# 配置解析、合并与传递

## 适用范围与职责

本设计规定 Sark 配置的共同处理机制，适用于 Vite 工程选项、应用核心、宿主、可选能力及可独立调用的客户端和中间件入口。后续能力沿用同一机制。

各领域继续拥有自己的配置类型、默认值、约束和解析实现。生成的组合根按依赖顺序连接这些实现，核心不维护包含所有能力的配置联合，也不扫描全量配置注册表。统一机制不要求把配置集中到一个大对象或一个运行时模块。

配置处理遵循以下顺序：

```text
配置声明及显式输入
  → 所属入口取得环境和必要依赖
  → 合并默认值、应用覆盖、规范化并校验
  → 将已解析配置交给装配和执行代码
```

每项默认值由所属领域唯一维护。其他模块使用解析结果，不复制默认值，不读取另一份环境来重新解释配置，也不在配置缺失时自行恢复为默认行为。

同一含义的默认值需要跨模块使用时，引用所属领域的轻量定义或传递解析结果；不同用途恰好具有相同数值，不因此合并为全局常量。

各专项文档维护具体配置项、单位、默认值、合法范围、启用条件和特殊合并规则。本设计维护共同规则；专项需要不同语义时，必须在相应字段处明确说明，不能由消费代码临时决定。

## 声明、解析与创建

### 配置入口

配置入口是接收应用声明或独立调用选项、负责将其转换成内部有效配置的位置。它承担环境求值、默认值合并、规范化和配置校验，下游接收转换后的结果。

`define*` 声明的配置类型统一命名为 `…Config`，解析结果为 `Resolved…Config`；客户端创建、单次请求、导航、签发及上游中间件的操作选项继续使用 `…Options`。配置对象或环境工厂的联合输入使用 `input`，解析后的配置使用 `config`。这是一致性约定，不改变各领域的处理职责。

各领域使用明确的解析函数，接收原始选项及所需上下文，返回所属已解析类型。装配负责调用和传递，不重新实现字段合并；不为统一调用形式引入通用配置基类、DSL 或全量运行时注册表。

应用的 `define*` 只保存声明、类型及所属初始化引用。依赖环境的默认值不能在模块导入或声明调用时提前确定；在相应宿主入口取得环境后，再由所属解析器处理。对象声明和环境工厂返回的对象经过同一套解析规则。

`createClient(options?)`、显式中间件等独立公开入口，允许调用方省略其契约中可选的选项，由该入口完成解析。框架内部已经取得完整配置时，直接复用解析结果，不因某函数也可独立调用而重复补值。内部函数存在可选参数，不等于它可以成为新的配置解析入口。

### 环境值与必填配置

预期由环境提供的必填值，原始配置允许接收 `undefined`，但属性仍须显式提供。例如 `secret: string | undefined` 可直接接收 `env.AUTH_SECRET`；所属入口验证存在性、格式及条件依赖，解析结果中的 secret 为有效 string。缺失且没有默认值时直接报告配置错误，不回落到其他变量或凭据。

该规则适用于密钥、数据库地址、平台 binding、OAuth 客户端信息、远端 API 地址及对象存储签名目标等配置输入；不将全部字段改为可选，不放宽 kind 等判别字段，也不改变配置模式的互斥关系。必需集合中的必需值同样在入口校验。

应用负责选择环境变量及业务特有的转换，框架负责自身配置项的有效性。字节密钥的编码转换仍由应用完成，转换函数可将缺失值保留为 undefined，再由入口校验；无效编码按转换规则报错。应用已有统一环境校验时可以继续使用，框架不要求额外的环境声明 DSL。

签发、验签、单次文件操作等操作接口仍接收有效参数；上游原生选项也沿用其本身契约，不随声明配置一并放宽。环境工厂的 Env 类型与宿主兼容性检查继续有效，不能通过断言把原始环境伪装成已校验对象。

### 配置工厂与业务回调

配置工厂只在规定的生命周期中执行，返回原始选项。请求处理器、身份映射、动态请求头、任务 handler、key 函数等业务回调保留函数引用，按各自业务时机调用；不能递归遍历配置对象，将其中所有函数当作配置工厂执行。

StoreDeclaration、日志 sink 等延迟创建函数在依赖资源就绪后调用，并由所属领域登记释放。它们属于资源创建，不通过配置合并过程提前打开连接、文件或定时器。配置表达方式和资源创建顺序见 [application.md](application.md)。

### 已解析配置

已解析配置必须满足所属契约：

- 有默认值的 Sark 字段已经补齐，单位和路径形式已经确定
- 必需字段存在且有效，依赖关系和目标平台满足要求
- 启用、关闭及合法缺省状态明确，下游可以按类型和既定分支直接处理
- 需要保留的函数、schema、binding 和资源声明仍保持原有语义，不转换成 JSON 或普通对象

完整不等于所有字段都必填。没有默认值且允许缺席的秘密、Host 限制或回调仍可缺席；只在启用某种模式后必需的字段，应由相应类型分支表达。未启用能力不填充空服务、无效凭据或伪造实例。

可选能力的启用规则由专项定义。框架已经约定的基础行为及依赖派生配置，由所属装配入口确定；消费方不能因为缺少配置而自行启用另一项能力。

## 输入与合并规则

### 缺省与显式值

字段缺席和显式 `undefined` 默认表示未提供。解析器按该字段的默认值或继承规则处理，不能让对象展开中的 `undefined` 覆盖已经补齐的结果。若字段明确区分两者，专项必须给出用途和处理规则。

`false`、`0`、空字符串、空数组和 `null` 不自动等价于未提供：

- 契约允许的值保留其含义，例如端口 0 或空可信代理列表
- false 仅在该字段允许关闭时表示关闭
- null 仅在类型允许时合法，不隐式当成空对象
- 不合法的值报告配置错误，不使用默认值替换

不使用 `value || defaultValue` 混淆合法的显式值与缺省值。字段的允许范围以所属契约为准，不能为了让值通过而擅自扩充含义。

### 对象、数组与具名集合

对象按所属字段规则合并。允许部分覆盖的对象，只补齐未提供的子字段；表示整体策略的对象，在明确覆盖时整体替换。不能用一个通用深合并函数决定所有领域的行为。

数组默认整体替换，空数组保留清空含义。中间件按执行层级串接、页面缓存 tags/vary 合并去重等已有专项规则继续有效，不将它们推广为全部数组的默认行为。

字典和具名集合明确规定按名称覆盖、保留默认项或拒绝重复项。例如响应头按大小写不敏感覆盖，单项 false 在入口移除对应默认项，不删除应用显式设置的同名头；日志输出映射按 [logging.md](logging.md) 处理。不得通过通用对象展开掩盖名称冲突。

解析器不修改调用方对象或共享默认容器。需要调整的数组、映射在解析时取得独立容器；schema、函数和平台 binding 不做无意义的深复制。下游按只读契约使用结果，不为此引入递归冻结或逐请求复制全部配置。

### 局部与单次调用覆盖

应用、目录、路由的覆盖，以及客户端实例与单次调用的覆盖，属于有明确输入边界的配置合并。

目录和路由声明保留未指定字段，在应用配置及目标作用域确定后，计算本次有效策略。优先级、可覆盖字段与中间件执行顺序由 [application.md](application.md)、[http.md](http.md) 及各能力专项规定。局部声明不能提前填入框架默认值，截断对上层配置的继承。

单次调用只覆盖允许调整的字段。合并从已解析实例配置出发，不重新附加框架默认值；执行代码直接接收本次有效选项。显式安装的独立中间件按其自身配置构造和执行，不与声明式策略猜测合并。

## 生命周期与环境隔离

### Node 应用与宿主

Node 标准入口先加载环境，再导入应用声明。应用与宿主在各自依赖可用、进入下游之前解析对应声明；同一应用实例或宿主启动过程复用该次结果，不重复执行同一配置工厂。

端口、生产模式、运行根目录等来源和优先级由所属专项规定。依赖这些信息的默认值在入口解析时确定，后续消费者不再次读取 `process.env` 或当前工作目录来补值。Vite 开发监听仍由 Vite 管理，不借用 Node 生产监听字段。

HMR 按既定生命周期交接旧实例，再为新版本解析配置和创建资源。配置更新产生新的有效结果，不在多个存活实例间原地修改共享配置；具体排空顺序见 [application.md](application.md)。

### Workers 事件

使用事件 Env 或 binding 的配置，在当前外部 Fetch/Scheduled 事件入口求值和解析；同一事件内的服务和内部调用复用结果。不能将第一个事件的环境保存在进程级默认配置中，供后续事件使用。

连接在建立时绑定所属有效配置及允许保留的资源，后续回调使用连接作用域，不借用最近一次 HTTP 请求。连接环境与释放限制见 [websocket.md](websocket.md)。

静态声明中不依赖事件的配置，由所属应用运行时解析并复用；依赖宿主的信息在宿主可用后确定，不提前到模块导入。多个实例或运行时即便使用同一声明，也各自拥有解析结果。可跨事件共享的结构不能夹带事件专属的配置、binding、身份或可变请求状态。资源的复用与释放仍遵循所属领域生命周期，不因配置复用而改为跨事件绑定。

CF 静态资源在平台直接交付，不执行应用配置解析或环境工厂。Worker 中的业务分发使用同一所属配置解析器，环境工厂只在实际进入 Worker 的外部事件中求值。静态安全头、缓存和跨域策略使用原生平台配置，不把运行期工厂提前到构建时执行。

### 回调及请求相关策略

请求 ID、客户端地址、身份、动态 key、回调返回值等按请求或操作取得，不提前固化为应用配置。局部策略在所需信息可用后完成合并；之后执行同一操作的下游复用结果。

配置解析不代替业务回调执行，也不把所有运行期数据都纳入配置对象。

## 工程配置与生成代码

### 工程入口

工程配置采用上游实际解析结果，不由 Sark 维护另一套 Vite 或 Wrangler 默认值、文件与环境合并规则。工程选项归属和具体接入见 [build.md](build.md)。

当上游配置需要多个生命周期阶段才能确定时，分阶段补充对应信息：Sark 自有默认值只合并一次，最终工程路径和输出信息以上游最终结果为准。后续阶段不重新解释原始 Sark 选项，也不因为上游值暂不可用而猜一个值传给下游。

多个生命周期阶段复用同一解析与生成流程。早期工作只消费当时已经确定的信息；最终消费者必须取得完整的最终结果，不能因复用流程而删除上游必需的阶段。具体生成时序由 [build.md](build.md) 规定。

### 下游传递

发现、生成、CLI、开发分发、HMR 和生产接入使用所属入口提供的已解析配置。内部生成器不再接受缺失的目标或前缀后自行补值，CLI 也不从残缺的插件选项重新推导构建目录。

工程前缀、运行目录、类型来源与构建产物信息都必须传到其实际消费位置。生成代码输出确定的值或引用所属运行期解析器，不把一份默认值逻辑复制进多个模板。

运行期工厂继续留到所属宿主执行；构建不为了生成完整配置而执行生产工厂、读取运行期秘密或创建资源。生成结果保留声明的环境类型要求，不能使用断言抹掉它们。

构建静态资源的目录、URL 和清单从最终构建结果派生，再作为宿主交付参数传递，不新增一套可独立偏离 Vite 的应用静态目录配置。可部署产物中的资源位置以实际产物布局解析，不携带构建机器的私有绝对路径。运行目录与资源交付见 [assets.md](assets.md)。

## 浏览器与独立消费入口

SSR 和浏览器共享的有效配置，由框架装配并明确交付公开字段。浏览器不因为缺少启动配置就自行补上 API 前缀、资源地址或传输选项；缺失违反契约的字段应暴露为配置或启动错误。

公开内容采用明确字段集合，不序列化整份服务端配置。服务端 API 地址、Env、密钥、配置工厂、身份回调和宿主私有路径不得进入浏览器产物或启动载荷。请求中决定的公开值随本次响应交付，不能在构建时执行环境工厂取得。

独立 HTTP 客户端、浏览器 helper 或显式中间件有自己的公开选项入口，按其契约解析默认值，不要求读取应用实例。框架绑定的实例使用所属应用或工程的解析结果；类型注册不提供运行时配置，独立客户端也不能凭注册类型猜测当前应用地址。

上游负责的选项和默认行为继续由其构造或配置入口处理。Sark 不复制上游完整默认表；装配时将有效选项传给上游，后续使用构造后的处理器或实例。Sark 自己承诺的覆盖、单位和启用语义仍由所属解析器完成。

## 下游契约与错误

原始选项类型描述应用可以省略的内容；内部已解析类型描述下游实际可用的结果。有默认值的字段在解析后应为必需字段；合法缺省和互斥模式保留准确的类型表达。

内部函数接收所属已解析类型或其明确子集，不把原始可选配置继续传下去。类型断言、非空断言和泛型实参不能替代合并与校验。配置只读不等于运行时深度冻结，也不要求所有配置对象具有相同形状。

下游不补配置默认值，不吞掉配置错误，也不以空配置、备用路径或静默禁用恢复执行。原本可选的能力分支和协议数据缺省仍按契约处理；不能把它们与缺失必需配置混为一谈。

字段检查集中在入口及实际依赖可用的最早位置，静态与运行期约束分别校验。下游不为每次字段读取重复进行防御性验证；若内部传递破坏已解析契约，按程序错误暴露和修复，不加回落逻辑掩盖它。

构建和 Node 启动时的无效配置使相应流程失败，失败后释放已创建资源。Workers 事件配置无效时，沿该事件的错误处理失败，不使用上一事件或另一套默认配置继续业务。错误响应可以使用入口已经确定的基础响应设置，但不能把失败的配置当作解析成功。

错误指出配置声明、字段及相关来源，保留必要原因；消息和日志不输出密钥、令牌或完整环境。配置解析不负责应用业务重试、权限跳转或数据库降级。

## 新能力接入与验证

新增配置时，所属设计和实现应能回答：由哪个入口接收，何时取得环境和依赖，哪些字段有默认值，如何表达关闭与缺省，如何覆盖，以及哪些下游消费哪些结果。新增能力不要求修改核心的全量配置类型或装配注册中心。

验证覆盖实际影响范围：

- 默认值、部分对象、显式 undefined、合法边界值和无效值分别产生正确结果
- 目录/路由及单次调用覆盖从已解析上层配置出发，未提供项正常继承
- 修改非默认前缀、目录或传输选项后，真实生成、启动和调用链使用同一结果
- 静态配置按所属运行时复用，失败结果不缓存；工厂按实例或事件解析一次，同事件内部调用复用，不跨事件缓存工厂结果、store、binding 或身份
- 解析不修改输入或共享默认容器；未启用能力不因补齐配置而被加载
- 浏览器只收到允许公开的值；声明、已解析类型、生成装配和目标平台入口相符
- 入口配置无效时失败，下游契约被破坏时不通过回落得到正常业务结果

测试须验证实际行为和关键传递链路，不能只断言默认对象包含字段或生成文本出现某个名字。类型夹具使用项目相同的编译目标与模块条件；不通过更改编译配置掩盖解析类型或生成代码的问题。
